## What was run

The Windows RTX 5090 served Qwen 3.8 27B Q6_K and Inkling 2 Mini IQ4_NL. Both models received the same synthetic inputs and per-tier budgets. Only the local inference endpoint was contacted. The Organism checkout was at 802adb8, plus the conversation fixtures alongside this report.

- **Business memory.** The existing [generator and verifier](../../src/businessMemoryBenchmark.js) provided 11 families in two synthetic companies. The same 22 questions were graded first with scoped company records and then with the repository’s authored procedures added. Temperature 0, sampling seed 7, low reasoning effort, JSON-object mode, 2,048 tokens per case including the native runner's 512-token answer recovery allowance. Generator seed `routed-baseline-20261121`, development pool. Manifest SHA-256 `3e6aaec8c0534007d9e608719ad5c9d7ab77a9848ce0435bd79caa5f5b3aef0c`.
- **Conversation workflows.** Nine two-turn families on seeds `baseline-20261121-a` and `baseline-20261121-b`. Each case uses a simulated tool server with paginated reads, persistent writes, revision checks, and a follow-up correction. Temperature 0, sampling seed 17, low effort, 12 model turns per user phase, 1,400 generated tokens per request. The case must pass both phases. The three formerly reserved structures are now baseline-visible: use fresh structures or independently held-back worlds for a blind promotion test.
- **Skill acquisition.** The [existing sequential-skill interpreter and verifier](../../src/sequentialSkillLearning.js) graded inventory reservation and draft invoicing. Each family started with an empty library and allowed three attempts to produce a reusable procedure. Acceptance requires correct native state and explicit completion in four validation worlds. This rerun reused the pilot demonstrations (seed `pilot-transfer-01`) and raised the per-attempt cap from 3,072 to 8,192 tokens on both models. Temperature 0, sampling seed 17, low effort, JSON-object mode. Procedures supplied in the business-memory tier and procedures synthesized here answer different questions.

## Reproduce

From the repository root, set `AMOS_BENCH_URL` to the OpenAI-compatible URL ending in `/v1`, set the API key through the existing credential store, and set `MODEL` and `WEIGHTS_SHA256` to the selected model and its weight digest. Specify fresh output paths for each run.

```bash
export AMOS_LOCAL_BENCHMARK_API_KEY="$AMOS_BENCH_API_KEY"
node swarm/scripts/runBusinessMemoryBenchmark.js \
  --workers "$MODEL|$MODEL|${AMOS_BENCH_URL%/v1}|generic" \
  --arms memory,procedures --pool development --worlds 2 --cases-per-family 1 \
  --seed routed-baseline-20261121 --reasoning-effort low --max-output-tokens 2048 \
  --json-mode --output "/tmp/memory-$MODEL.json"
bench=swarm/evals/conversation_workflows
python "$bench/corpus_challenges.py" --base-url "$AMOS_BENCH_URL" \
  --models "$MODEL" --seeds baseline-20261121-a baseline-20261121-b \
  --output "/tmp/workflows-$MODEL.jsonl"
node "$bench/skill-transfer.mjs" --base-url "$AMOS_BENCH_URL" --model "$MODEL" \
  --weights-sha256 "$WEIGHTS_SHA256" --seed pilot-transfer-01 --max-output-tokens 8192 \
  --output "/tmp/transfer-$MODEL.jsonl"
```
